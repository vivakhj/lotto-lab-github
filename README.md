# 로또랩 · 통계로 고르는 여섯 숫자

한국 로또 6/45의 **1회부터 최신 회차까지 실제 당첨번호**를 분석하는 웹앱입니다. GitHub Pages에서 사용할 수 있고, 별도 서버·유료 API·로그인이 필요 없습니다.

**초기 포함 데이터: 1~1244회, 2002-12-07 ~ 2026-10-03.** 2026-10-10 제작 시점에는 당일 저녁 추첨 전이므로 1244회가 공식 최신 회차입니다. 1,244개 회차의 누락·중복·번호 범위·보너스·추첨일을 검사했으며, 45개 번호의 누적 출현 횟수를 동행복권의 별도 통계 경로와 대조했습니다.

통계가 당첨 확률을 높인다는 근거는 없습니다. `1, 2, 3, 4, 5, 6`을 포함해 어떤 특정 조합의 1등 확률도 **1/8,145,060**입니다. 통계와 형태 필터는 번호를 고르는 기준입니다.

## 1. PC에서 먼저 실행

1. ZIP을 압축 해제합니다.
2. `dist` 폴더의 `index.html`을 Chrome 또는 Edge에서 엽니다.
3. ‘나의 번호 추천받기’를 누릅니다.

웹앱은 포함된 당첨기록으로 작동합니다. 로컬 파일 실행에서는 네트워크 데이터 갱신·홈 화면 설치가 제한됩니다. 정기 갱신은 아래 GitHub 배포를 완료한 뒤 동작합니다.

## 2. GitHub에 올리기 — 웹사이트에서 진행

1. [GitHub 새 저장소 만들기](https://github.com/new)를 엽니다.
2. Repository name을 `lotto-lab`처럼 정하고 **Public**을 선택합니다. 공개 저장소는 GitHub Free의 Pages를 사용할 수 있습니다. 공개된 내용에는 앱 코드·공개 당첨기록이 들어가고, 개인 저장번호는 사용자 브라우저에 남습니다.
3. **Create repository**를 누릅니다.
4. 빈 저장소 화면에서 **uploading an existing file**을 누릅니다. 파일이 이미 있는 저장소라면 **Add file → Upload files**입니다.
5. 압축을 푼 최상위 폴더의 **내용 전체**를 업로드 영역에 끌어 넣습니다. `lotto-lab-github`라는 바깥 폴더 자체를 한 단계 더 넣지 않습니다.
6. 업로드 목록에 `dist/index.html`, `scripts/update_lotto.py`, `tests/core.test.cjs`, `.github/workflows/lotto-pages.yml`, `README.md`가 보이는지 확인합니다. ZIP 자체를 업로드하는 것은 배포가 아닙니다.
7. **Commit changes**를 누릅니다.
8. **Settings → Pages → Build and deployment → Source**에서 **GitHub Actions**를 선택합니다.
9. **Actions** 탭에서 **Lotto data update & GitHub Pages**를 선택합니다. 초기 실행이 Pages 설정 전에 실패했으면 **Re-run all jobs**, 실행이 없으면 **Run workflow**를 누릅니다.
10. 완료 후 **Settings → Pages**에 표시되는 실제 주소를 엽니다. 보통 `https://사용자이름.github.io/lotto-lab/` 형식입니다.

저장소 목록에서 `.github/workflows/lotto-pages.yml`이 보이지 않으면 자동 갱신이 동작하지 않습니다. **Add file → Create new file**로 이 경로를 입력하고 동봉된 같은 파일의 내용을 붙여넣어 생성할 수 있습니다.

## 3. 매주 자동 갱신

자동 작업은 한국 시간 기준 아래 시각에 공식 결과를 확인하고 다시 배포합니다.

| 실행 | 한국 시간 | 목적 |
|---|---|---|
| 1차 | 토요일 22:31 | 당일 추첨 후 확인 |
| 2차 | 일요일 09:41 | 반영 지연·일시 실패 재확인 |
| 3차 | 월요일 09:43 | 추가 재확인 |

GitHub 예약 작업은 지연되거나 누락될 수 있습니다. 원할 때 **Actions → 해당 작업 → Run workflow**로 다시 확인할 수 있습니다. 마지막 확보 회차와 추첨일은 웹앱에 표시됩니다. 토요일 22시 이후 새 회차가 없으면 반영 지연 가능성을 알립니다.

동행복권이 접속을 제한하거나 데이터 형식을 바꾸면 자동 갱신이 실패할 수 있습니다. 검증된 기존 데이터는 유지되며, 실패한 실행은 Actions 로그와 앱 상태에 표시됩니다. GitHub에서의 공식 사이트 접근은 실제 계정 배포 후 처음 확인됩니다. 공식 외에 프록시나 임의 데이터로 대체하지 않습니다.

기본 브랜치는 `main` 또는 `master`로 두세요. 예약 작업은 기본 브랜치에 있는 파일만 실행합니다. 저장소에 브랜치 보호 규칙을 추가해 자동 데이터 커밋을 막으면 작업 설정을 함께 조정해야 합니다. 공개 저장소에서 장기간 활동이 없으면 GitHub가 예약 작업을 비활성화할 수 있으므로 Actions 상태를 확인하세요.

## 4. 사용 기능

- 기본 5게임 추천, 1·3·10게임 선택
- 전체 통계·최근 통계·70:30 혼합·균등 무작위 추천
- 최근 10·26·52·104회 분석
- 1~45 전체 빈도, 미출현 회차, 마지막 출현, 동반 출현 통계
- 고정 번호·제외 번호, 선택 가능한 형태 필터
- 추천별 전체·최근 출현 기록 확인
- 내 번호 저장·복사, 대상 회차 결과 비교, 수동 번호 당첨 확인
- 전체 당첨기록 CSV 다운로드
- iPhone/iPad/Android 홈 화면 추가 및 오프라인 기본 화면

내 번호는 `localStorage`에 최대 100게임 저장됩니다. 다른 브라우저·기기·도메인과 공유되지 않습니다. 브라우저 데이터 삭제 시 사라집니다. 새 결과가 데이터에 반영되면 저장된 대상 회차와 비교합니다. 복권 구매 여부는 확인하지 않습니다.

## 5. 추천 계산

보너스 번호를 제외한 당첨번호 6개만 계산합니다. 분석 회차 수를 `N`, 어떤 번호의 전체 출현 횟수를 `f`, 최근 회차 수를 `R`, 최근 출현 횟수를 `r`이라 하면:

- 전체 기록 값: `(f + 1) / (6N + 45)`
- 최근 기록 값: `(r + 1) / (6R + 45)`
- 혼합 값: `전체 기록 값 × 0.7 + 최근 기록 값 × 0.3`
- 번호 선택 가중치: 해당 값의 제곱근. 모든 번호에 양의 가중치를 주고 빈도 차이를 완만하게 반영합니다.
- 중복 없이 가중 추출해 6개를 뽑고 활성화된 조건을 만족하는 조합만 채택합니다.
- 같은 생성 묶음 안에서 동일 조합은 중복되지 않습니다.

미출현 회차·동반 출현 횟수는 참고 정보이며 가중치에 넣지 않습니다. 가중치는 **이 도구가 번호를 선택하는 방식**이며 미래 당첨 확률·예측 점수는 아닙니다.

기본 형태 필터는 홀수 2~4개, 저번호 1~22에서 2~4개, 역대 당첨 조합 합계의 10~90백분위 범위, 3개 이상 연속번호 제외입니다. 과거와 같은 조합 제외는 기본으로 꺼져 있습니다. 모든 필터를 끌 수 있습니다. 균등 무작위에도 켜둔 필터는 적용됩니다.

고정·제외·형태 조건이 맞지 않으면 오류로 안내합니다. 임의로 조건을 풀거나 일부 게임만 성공한 것처럼 표시하지 않습니다. 6개를 모두 고정하면 1게임을 선택하세요.

## 6. 파일과 개발 명령

| 경로 | 역할 |
|---|---|
| `dist/index.html` | 웹앱 시작 화면 |
| `dist/app.js`, `dist/styles.css` | 화면 동작과 디자인 |
| `dist/lotto-core.js` | 통계·추천·당첨 판정 |
| `dist/data/lotto.json` | 검증된 전체 당첨기록 |
| `dist/data/lotto-data.js` | 로컬 실행용 동일 데이터 |
| `dist/sw.js`, `dist/manifest.webmanifest` | 홈 화면 설치·오프라인 캐시 |
| `scripts/update_lotto.py` | 공식 데이터 수집·검증 |
| `.github/workflows/lotto-pages.yml` | 정기 갱신·검증·Pages 배포 |
| `tests/` | 데이터 보존·추천 조건·당첨 판정 테스트 |

Python 3.12+와 Node 22+가 있는 개발 환경에서:

```bash
python scripts/update_lotto.py --validate-only
python scripts/update_lotto.py
python -m unittest discover -s tests -p 'test_*.py'
node --test tests/core.test.cjs
```

`--bootstrap`은 초기 데이터 파일이 없을 때 1회부터 새로 수집하는 옵션입니다. 이미 포함된 파일은 그대로 사용하면 됩니다. 브라우저가 공식 사이트에 직접 교차 출처 요청을 하지 않도록 수집 작업과 웹앱을 분리했습니다.

## 7. 확인한 범위

- 1~1244회 전체 데이터 검증 통과
- 45개 번호 누적 빈도와 별도 동행복권 공식 통계 결과 일치
- 4개 모드, 총 1,000개 추천에서 고정·제외·형태 조건 및 조합 중복 검증
- 1~5등·보너스 판정, 오류 데이터 거부, 갱신 실패 시 기존 기록 보존 테스트 통과
- JavaScript 문법, HTML 연결, 배포 파일·워크플로 구조 확인
- 실제 브라우저 시각 검사와 사용자 GitHub 계정에서의 예약 실행은 미확인
